# GitHub Security alert remediation (2026-10-23)

This review addresses GitHub Security alerts in `microsoft/DocAtlas-Harness`,
covering the original CLI and independent Web workspace from base `ec91b2f`.
The initial snapshot contained 63 Dependabot alerts (4 critical, 20 high,
34 medium, 5 low) and 19 CodeQL alerts, with no open secret-scanning alerts.
Dependabot counts include repeated matches across manifests and advisories;
they do not represent 63 distinct vulnerabilities.

## CodeQL alerts

The 18 `js/bad-code-sanitization` alerts concern extension code generated by
four test files. A shared `javascriptString()` helper uses JSON string encoding
and then escapes `<`, `>`, U+2028 and U+2029. Five added tests check that quotes,
backslashes, closing script tags, control characters, Chinese text and emoji
round-trip as data without executing injected code.

The `js/clear-text-storage-of-sensitive-data` alert (#20) is a session-cookie
false positive: the name `secret()` triggered a credential heuristic, although
the function produces independent tokens from 32 random bytes. The server
already indexes sessions by token hash; cookies contain no passwords, bootstrap
codes, CSRF tokens or actor data. The generator is now named `randomToken()` with
comments explaining its purpose. Added assertions verify cookie-content
separation and distinct tokens across sessions. HttpOnly, SameSite=Strict,
HTTPS Secure, expiration and revocation behavior are preserved. This change
does not claim to fix a previously existing cleartext-password storage defect.

No CodeQL rules were disabled, no affected test files were excluded, and no
GitHub alerts were manually dismissed. Local analysis with CodeQL 2.27.3 and
`codeql/javascript-queries@2.4.8` completed successfully with **zero results**
for these two rules. This was a targeted recheck of the reported rules, not a
scan with the full CodeQL query suite.

## Secret scanning and scope

The **14** new lockfile findings were reviewed individually: 13 exactly match
npm registry `dist.integrity` values, and one is a pnpm configuration checksum
validated by a frozen install. New baseline entries contain only these verified
non-secret finding hashes. The scanner also refreshed line numbers and removed
19 obsolete checksums from the previous locks. Scanner plugins and filters are
unchanged. The baseline contains 1728 findings, all audited as `is_secret: false`.
An independently generated synthetic secret triggered both high-entropy and
Secret Keyword detection in the same scanner.

No real model services were called. Real-corpus Docling conversion, OCR, GPU
conversion and performance were not revalidated; byte-for-byte equivalence of
old and new Docling output is not established. Browser end-to-end journeys and
the actual Python 3.11 / 3.13 test matrix were not run. These remain outside the
local Python 3.12.12 validation described here.

This report records the changes and local verification. Publishing the fix
branch does not close alerts on the default branch; closure must be confirmed
after merge and GitHub rescanning.
