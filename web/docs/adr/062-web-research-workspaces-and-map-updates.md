# ADR-062 · Web Note / Review 工作面与研究地图更新

状态：本轮体验已接入，浏览器验收及旧笔记初始化回归补验通过，准确范围见任务板。承接用户追加要求及research/15的正交能力设计，不以旧Note/Review工具名定义产品。

## 现状核对

- Note已有人类独立正文、选区锚定、问题/决策/规则、版本化编辑与归档/删除、原件回跳；入口和长表单主要隐藏在More里。
- Review已接真实Evidence/Claim/Artifact、确定性G0–G4、独立人工决定、发布和原键恢复，不是原版Recall式辅助模型挑Note。
- Tree Update的既定定义是可重建的Research Overlay（ADR-012、research/15 §8），不是覆盖canonical tree。当前Web有页级研究标记，但Document Map尚未组合这些状态。

## 本轮实现范围

1. 让Notes与Review成为明确的Web研究入口；桌面直接可见，窄屏采用紧凑Research入口。保留简洁聊天起点和所有已有授权、原键、版本检查。
2. Notes采用记录列表与编辑/来源详情的分区工作面。保留独立笔记、评论/假设/草记、问题与用户决策/规则，不强迫转成Claim或个人Memory。默认低摩擦正文捕获，来源、状态、版本和治理按需展开。
3. Review提供真实关系可视化和检查进度：Evidence → Claim → Artifact → Review，支持/反驳/限定和G0–G4状态有文字及颜色区分。保留原始规则失败、coverage与独立人工签署，不画虚构分数或将自动检查等同事实正确。
4. Map增加Original / Research视图。原始章节不改；经过授权的Note/Question以及Claim/Review相关状态作为独立研究节点或标记挂入地图。派生连线用虚线，明确它们不是PDF章节。
5. 新增研究采用青绿色，记录新版本采用琥珀色，原始目录保留原样。颜色之外显示类型、版本、页码、状态；这是相对原结构的新增/修订，不声称用户已经阅读或“刚刚发生”。
6. 编辑、解决、归档或删除作用于真实domain records；地图从最新记录重新投影，删除撤回标记。刷新只读，不生成模型输出、不伪造新目录、不写第二份研究账本。
7. 只按完整source/revision/representation/hash与已存Locator投影；章节范围仅能定位到页时明确提示。多个章节同页不能猜精确章节，可挂到共同祖先/文档下并保留页码和原件精确回跳。

## 明确边界

- 不实现任意canonical章节重命名、重排、删除；那不是既定Tree Update语义。隐藏研究层只是视图筛选，不删除事实源。
- 无锚Agent checkpoint仍可在Notebook/Recall查看，但不猜位置塞进Map。
- 不新增泛化memory工具，不把人类Commentary当文档证据，不自动签署、发布、启动模型或扩展资料范围。
- 若显示范围/记录预算被截断，明确提示并允许继续读取；没有加载的数据不计为不存在或已通过。
- 与ADR-061的章节摘要、问答选区历史同时保留，不能为新功能退化原PDF或独立A/B阅读。
- 本轮新入口、地图与关系图提供EN/中文。沿用的详细治理/审阅表单仍有中文文案，完整英文与表单进一步简化待续，不以新增双语入口声称全部历史界面已翻译。

## 验收

实现说明：`MapResearchAccess`读取授权的当前研究Note/Question及匹配source的Review历史frame，`recordVersions`仅附加当前版本/作者元数据，`scopeOptions.sourceRefs`仅在32源以内完整返回。旧响应可无新字段。地图最多60研究节点，Review图每列12条，有界截断明确提示；直接关联另有可操作文字列表。记录/原件打开仍由既有授权与原键链负责。

回答瘦身：删除两组回答级details及重复免责声明，LiveApp不再挂载独立LiveProbe。保留引用tooltip、弱定位禁用、历史来源标识与源核验失败提示。Review工作面是本轮明确要求的独立功能，不随Answer options被删除。旧Probe API/合同/原键测试继续；仅依赖已删除入口的浏览器旅程显式退役，由回答页面缺席断言替代，新自然入口尚未设计。
