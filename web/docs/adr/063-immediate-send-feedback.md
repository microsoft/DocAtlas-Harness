# ADR-063 · 回车发送的即时、可信反馈

状态：已接入并通过定向及桌面/手机浏览器验证。用户指出回车后长时间无反应，消息随后突然出现。

原因：当前UI只展示服务端run/native history；本地请求即使已冻结，也没有消息投影。收到回执后先清空输入，再等snapshot补全文字，期间会出现空白/“正文尚未同步”。首屏布局和滚动也只跟snapshot变化。

决定：

- 明确发送时立即冻结同一原请求并显示本地发送预览；它不是已保存的native message，不写第二份会话或服务器receipt。
- 本地预览、精确匹配回执、run正文、native用户消息按真实identity接力；相同文字不用于去重，不能把观察流receipt当成原文历史。回执先到、snapshot迟到不能丢失本地正文。
- 输入视觉上随发送反馈清空，但原稿/来源/选区/原键继续按既有tab outbox保留；失败或结果未知保留可见原文和明确重试，刷新不自动重发。
- Enter/按钮统一同一发送路径，Shift+Enter与输入法组合不发送，重复Enter不新建请求。实际新会话建立仍须原键证明，不在错误会话中展示本地预览。
- 发送预览有轻量进场和紧凑待确认状态，滚动只在用户跟随消息时进行；减少布局突跳并尊重reduced-motion。模型开始/完成仍由真实状态决定。

验收：延迟/丢失accept、SSE先于POST回执、snapshot缺少正文、同文本重复发送、重新加载与换会话隔离、中文输入法、手机和选区提问。不得以即时气泡冒充已接收或后台加速。

结果：全量JS/Python检查通过；真实隔离Pi + 受控provider在1440/390px下，暂停提交网络仍在1秒断言内显示发送气泡；确认前后clientWidth/clientHeight差不超过2px。Shift+Enter、组合输入、连续Enter、相同正文不同原键、刷新不重发均通过。发送状态置于消息间距内，不在确认后撑大/缩小气泡。首个无会话问题仍先完成真实创建，不声称后台或模型耗时已缩短。
