# ADR-057 · Answer 排版、长回答引用与原 PDF 文字层定位

状态：接受有界修复；不代表全文语义核验或任意 PDF/OCR 定位已经完成。

## 实际问题

2026-09-10，用户反馈标题 `## 5. 实验设计` 原样显示、正文反复插入“出处待核验”、部分引用仅能打开原始页。
只读检查当前已发布 Answer，发现 `limit-exceeded`：Core 编译器最多保存 16 条引用，但 v1 contract 已允许 128 条。
“超过 7%”对应的事实片段位于上限之后，已保存记录没有该片段的 citationId；这不是对数字真假的判断。
另有未分类文本也被逐段追加同一提示，包括标题和连接段落，造成错误的阅读体验。

该论文全部 16 个已保存引用服务端均能严格 resolve。原 PDF 浏览器文字层中，旧拼接在所有 text node 之间强加空格：
`BERT36` 变为 `BERT 36`、`2)` 变为 `2 )`；源提取还出现 `MBPP ,` 与 PDF.js `MBPP,` 差异。
这是显示定位问题，不能以换跳 Markdown、近似数字匹配或绘制虚假框解决。

## 决定

- 使用固定版本 react-markdown + remark-gfm，支持标题/列表/强调/引用块/代码/表格，覆盖已保存、无manifest及生成中回答。
- 原始 HTML 仅作为文本，不执行；模型图片不发请求，模型链接不成为导航或引用。
- 只有 manifest 事实片段生成的展示链接，且 AST 起止偏移和内部地址均与宿主生成值相同，才能渲染对应 citation 按钮。
  保持 read-verified、精确 source/revision/hash、publication/checkpoint 和原件路由核验；不从裸 marker 推断可信出处。
- 未关联出处在回答末尾折叠解释一次，细分容量上限、未知 Locator、格式错误及缺少读取原文；保留具体 unresolved 事实文本。
- 编译器引用上限对齐现有 128 条 contract，另以 256 KiB 限制引用元数据累计大小。超限仍留下显式 unresolved/warning，保留整体 512 KiB 验证。
  本次不修改协议字段、版本或数据库。只影响新编译的 Answer；不重写旧 manifest、hash、native history 或自动重问。
- PDF 文本按真实文字节点连接，仅在 PDF.js 的 BR 处加换行，不人为分隔上标/标点。显示匹配仅额外容忍“字母词后、逗号前”的提取空白差异；保留原 DOM offset。
  数字/单词内部边界、大小写、标点不能近似改写；所有匹配仍要求唯一。此规范化只用于显示，不改变原文、Evidence 或选区准入。
- Reader 提示区区分 source resolve 只到页、原文重复、无文字层和浏览器文字层不匹配，不再用一个模糊提示覆盖全部原因。

## 验证与限制

新增安全 Markdown、长回答/大 Evidence 字节上限、排版空格/数值反例测试；实际 Pi+sidecar+PDF 浏览器旅程覆盖标题、表格、出处和上标 PDF。
运行结果记录在执行任务板。额外检查用户已保存回答及原 PDF 不调用模型、不改历史、不把私人论文加入仓库 fixtures。
老回答超过原 16 条上限的引用不会凭本次显示修复自动补齐；新回答使用新上限。重复原文、OCR、跨栏阅读顺序及其他提取差异仍可能诚实降级。
