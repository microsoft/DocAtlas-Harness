# ADR-059 · 一次选区操作即可附上原文，不允许静默漏带

状态：已部署并通过端到端回归；沿用现有selection-stage/one-shot ticket合同，不改证据或模型权限。

## 实际问题

用户反馈选中原文后点击Ask about this没有效果。只读检查实际最近“翻译为中文”提交，其selectionContextIds/sourceRefs均为空；选区库没有生成过ticket。
旧Ask按钮仅打开待核验区，用户还需再次点击Verify and add to question，然后输入问题并发送。待核验区存在但未点击Verify时，发送仍可执行，导致原文选区被静默遗漏。
长选区还把操作挤在滚动托盘底部，按钮缺少间距和明确下一步。

## 决定

- 用户主动点击Ask about this即授权对该精确选区调用现有核验接口一次，自动附入下一条问题；单纯划选仍不调用模型/核验或写Note。
- 输入框可以在核验中继续编辑。成功后保留用户已有草稿；仅当草稿为空时填入当前界面语言的可编辑“Explain this selected passage.”建议，并聚焦输入框。
- 最后由用户明确发送，不因选区或语言切换自动调用模型。模型收到的仍为原selectionContextIds经绑定/实际消耗后的核验原文，标记为不可信source data而非指令。
- 待核验/核验中/失败/恢复待办/损坏待办全程关闭发送闸门，覆盖按钮与Enter。只有成功附入或明确舍弃解除，不允许降级成“没有选区的问题”。
- 原请求body/key保留供显式重试；刷新不自动重做请求。持有闸门有独立owner，旧清理回调不得释放新的选区操作。切换会话/绑定卸载后，迟到返回不附入新上下文。
- 当前选区若已附入且ticket未过期，重复Ask只回到同一草稿，不创建重复ticket。核验失败时重选需先舍弃旧待办，不悄悄替换未知操作。
- 卡片默认两行摘要、点击展开全文，状态、重试/舍弃各有清晰位置；成功显示已附上/可以提问。保留回原文、撤销与仅本地移除的区别。

## 验证

英文默认真实浏览器旅程覆盖多行长选区、核验中Enter、保留翻译草稿、默认问题建议、重复Ask、不匹配失败/刷新/舍弃、原键丢回执重试，以及同一Pi执行真实收到quote/ticket且仅消费一次。
只使用仓库合成PDF与受控测试provider；不重新发送用户的私人段落或改写已有回答。最终检查记录见执行任务板。
