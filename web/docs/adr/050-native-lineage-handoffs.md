# ADR-050: Native selected heads, branch/fork handoffs and historical origins

- Status: Accepted and integrated in Batch24; real SDK/host/HTTP/browser verification recorded separately from final Stop follow-up checks; not full native parity acceptance
- Date: 2026-09-09
- Extends: ADR-021/024/029/035/039/048/049

## Decision and actual SDK evidence

Use the real Pi `AgentSession.navigateTree` and `AgentSessionRuntime.fork`; do not create a second loop, copy product receipts into fake native conversations, discard native extensions, or redefine fork as an unrelated empty chat. Keep the old native-control protocol for settings/manual compact and add independent `native-lineage.v1` for the different selected-head and cross-session semantics.

Actual SDK experiments establish that navigation to a user/custom message selects its parent and returns native editor text; without a summary/label it changes selection but not file bytes. Navigation keeps the live model/thinking level even when the chosen older branch records different settings. Fork makes a new native session/file, copies the selected path, removes/rechains label nodes and recreates resolved labels. Original non-label IDs remain, but a byte-identical file-prefix proof is not a valid inheritance check. Native before/after hooks can cancel, append metadata, summarize or fail after an actual change. A cancelled signal alone is not proof of rollback.

## File integrity is not selected-head identity

`NativeFileSeal` explicitly contains version, native session, complete prefix hash/bytes/entry count and **tailEntryId**. `NativeSelectedHead` separately contains that seal, **selectedLeafEntryId** and a hash of the canonical actual public SDK `buildSessionContext` for that selected parent chain. Root selection is explicit null and retains the SDK's actual `{messages: [], model: null, thinkingLevel: 'off'}` context; it never defaults to file tail.

Verify bounded native bytes and topology independently. Historical fixed prefixes may permit later appends; cold restore requires an exact complete-file match. Before extension factories, open through public SessionManager and explicitly `branch`/`resetLeaf` to the verified selected ID. Do not modify private SDK state, infer selection from a filename/timestamp/last row, or run factories before unresolved state is checked. Existing native-control v1 prefix fields keep their meanings.

## Native operation proof

The whole command pins source binding/generation/session, selected head, resource approval/version and idempotency key. Navigation includes target entry, summary choice, bounded instructions, replace-instructions and optional label. Fork includes an actual native target entry and the SDK `before`/`at` position. A browser supplies neither a new session ID nor a filename.

Persist an intent on the source branch, invoke the actual SDK with its native hooks and cancellation, then record completion on the actual target branch. Navigation's completion need not descend from the source intent: it deliberately crossed branches. Verify the original prefix, intended SDK landing, actual selected result, any real branch-summary ID/from-ID/hash, effective configuration and both identities. Persist the actually preserved navigation model/thinking through public native metadata so live and cold contexts agree, without changing live model behavior.

Fork produces distinct source and target seals/selection/configuration witnesses. A private factory-entry observation captures the actual child inherited-entry boundary before child resource factories, without changing SDK output. Independently reconstruct the SDK's non-label path, parent links, compaction retained-entry remapping and resolved labels. `inheritanceHash` covers canonical inherited non-label rows and resolved `{targetId,label,timestamp}` descriptors, not the new header/markers. `forkBasisSeal` identifies a sufficient verified source prefix whose inheritance exactly matches the child; it does not guess when copying occurred. If hooks append/change labels before fork and again during shutdown, match the real source-prefix sequence to child content; do not simply use final labels or disable those hooks. Equivalent sufficient prefixes may use the earliest match. Missing/ambiguous evidence fails closed.

Source and target markers link the original operation and each other without circular file hashes; their public proof contains IDs/hashes, never private paths or raw transcript/editor text. A worker may return a private fork basename through inherited IPC; the host resolves it only inside the original granted session directory and revalidates bytes/header/lineage. A fresh SDK session ID is installation data, not browser authority.

Preserve inherited DocAtlas native metadata unchanged. Foreign-session control markers are history, not child operation proofs or queue preferences. A host-verified lineage configuration seed identifies the actual terminal marker and configuration. On restore, choose the latest seed/local control commit by **selected branch order**, not append order; child queues reflect the real new SDK runtime, not a copied parent marker. Runtime factories resolve model/thinking per new SessionManager; initial overrides must not silently override fork context.

Known non-application requires joined SDK/effects and independently proved unchanged selected context plus exact intent/terminal metadata, with no hidden new file or unrelated mutation. Veto/error text is insufficient. A change already applied before a rejecting after-hook is reported from actual proof. Unprovable outcomes remain unknown. Summaries are auxiliary context, not Evidence, a user question, or answer-generation MemoryUse.

## Product handoff and bounded recovery

Catalog v2 adds selected-head/configuration fields and a dedicated durable lineage journal; ControlStore retains its schema. The reviewed non-destructive catalog v1→v2 migration validates the original layout in a transaction and preserves rows/seals. Active owners or unknown schema/objects are not migration permission and must not be cleared. This batch tests temporary databases; it does not authorize moving user stores or running a production-data migration during development.

Reserve a handoff under the existing writer and claim before SDK effects. Unlike ordinary settings, prevent new submissions from entering the source generation while a binding handoff is reserved. Stages are reserved → native-proved → joined → installed → binding-committed → complete. The source/target slots remain durably fenced throughout; regular cold startup cannot run factories while a handoff is unfinished.

Do not close a coordinator from inside its own native-task callback. Finish that callback behind a durable barrier, then the manager drains SDK work, already-admitted native/model/document handlers and actual namespaces. Fence late broker admissions before joining and retain whole-operation budgets; timeout requests termination, never assumes completion. Only after actual join may the manager record joined state, install target data, transfer binding/catalog authority and allow a fresh writer.

For navigation, retain the native file/session but CAS the product binding to generation/version +1 and a new binding ID. For fork, preserve the parent binding and create a new conversation/binding with the SDK-produced native ID. Exclusively install the exact SDK-generated child file into the dedicated child runtime directory after join; fsync file and directory, preserve the SDK parentSession header, and never overwrite different existing bytes. Retain the original staging input for recovery rather than delete on TTL. An exact existing installation is accepted only for the same operation/proof.

ControlStore `commitNativeHandoff` checks exact preplanned source/target identities, actor/workspace and writer/pending barriers. Catalog archives immutable source binding and lineage references. Cross-database windows are explicit roll-forward stages, not a claim of cross-WAL atomicity. The final Catalog transaction records the immutable public receipt and clears the source/target fences together. An explicit original-key retry can finish metadata-only installation/binding/publication stages; GET is read-only. Unjoined/unclean ownership never permits a guessed takeover or rerun of the SDK operation.

Recreate worker, scheduler, document/research frames and observations from the actual selected native state. Generation changes close old SSE/cursors and stale browser identities. A selected historical source or inherited message is not new source admission; old selection tickets cannot be consumed in a new binding. Note/Review/Profile and published research are not rolled back by changing a native branch.

The new Web pins `POST /stop` with `If-Match: "<bindingId>"`. Every native handoff allocates a new binding ID; the handler checks the exact quoted ID before cancelling, and the manager rechecks its captured binding after waiting for an owned runtime. A stale condition returns the existing product `conflict` response (HTTP 409) without calling cancellation. The JSON body remains `{}` and older clients without the header retain the explicit conversation-current Stop API; they do not gain generation-CAS semantics. Duplicate, weak, wildcard or malformed tags are rejected rather than treated as a bypass. A stopped receipt still waits for actual native/effect joins, not just an abort signal.

## Historical reading and immutable publications

The history authority for a newly selected/forked view is the independently verified selected native head, not a fabricated `ProductPiCheckpoint`. A later real question receives its normal checkpoint. Page only visible user/assistant text with the existing display budgets; hide tools, thinking, provider/system payloads and raw prepared user text. Original human drafts must come from exact original ControlStore submission associations; SDK-returned editor text is never blindly inserted in the browser.

Resolve inherited/historical message origins through complete Catalog lineage and exact native entry inheritance/ancestry. Reauthorize the current and original conversation before history counts/cursors. Owned native chat is retained execution history: revoking a document grant does not erase text already present in that transcript. This is the existing Pi history boundary, not a claim that old chat remains an authorized source or Evidence. Every canonical Answer/citation/PDF access independently reauthorizes its original publication and sources for both original and viewing conversations. Source revocation can therefore leave the owned chat readable while making the structured Answer and PDF inaccessible; full transcript/privacy erasure is a separate operation, not silently inferred from a source exclusion.

Keep the original Answer manifest, publication binding/generation/checkpoint and Evidence IDs unchanged. A current view may reference an authorized original Answer; it must not relabel old Read attestations or old publication as a newly verified answer. Recheck origin, selected head and permissions after awaited reads. If original user payloads or conversation authority are gone, show unavailable or refuse access, never prepared prompt injection. Same-conversation published research remains readable off the currently selected native branch through original authorized publication frames. Cross-conversation inherited Answers require exact selected-branch membership and copied native text; a full-tree preview is not that authority.

The controlled presentation Probe remains owned by the original Answer conversation. Same-conversation navigation keeps it usable through its historical publication. Cross-conversation inherited Answers remain readable/clickable but their Probe control explicitly directs the user to the original conversation; do not relabel the canonical manifest or silently duplicate a preference vote into the child. Extending Probe commands across conversations needs a separate original-frame contract review.

The Web keeps chat-first and exposes branch navigation/fork on demand. Freeze command/head/approval/body/key and ownership in a versioned tab-local outbox; refresh inspects rather than executing again. Explicit original-key POST may reconcile a previously accepted operation only after full original ownership/body/hash verification, even if SSE has already advanced the binding generation. Apply a target binding only after the complete durable product receipt, preserve unrelated drafts, and distinguish native change applied/installation pending/unknown from ready-to-continue. Historical citations still open and highlight the original PDF, not Markdown. Prior-generation run receipts remain in execution storage, not fabricated question bubbles on the selected branch.

## Required verification

Shared Node/static-browser/Python shape/semantic vectors; selected≠tail/root/tamper/cold-before-factory tests; real SDK navigation/veto/summary/labels/model/queue/fork/rebind tests; hook writes before/after copy; exact inheritance without removing foreign metadata; writer/queued/stop/late-effect/closed-namespace tests; every handoff crash window and original-key-only roll-forward; same-source/new-generation and new-conversation history/citation authority; original user redaction; real paired PDF browser navigation/fork/refresh/retry/new question and accessibility checks. Scripted model summaries do not prove model quality. Full host-death supervision, automatic in-turn compaction/steer attribution and public deployment remain separate gates.

## Observed Batch24 integration

The full workspace check passed with 195 JS files (2514 passed, one existing opt-in skip) and 1275 Python tests, including finite-vendor and packaged provenance checks. The final Stop binding-precondition fix was later: all packages/types/lint were rebuilt once under sole-producer ownership and 74 focused host/client tests passed on that code. Real application-backed browser navigation/fork and genuine provider-cancelling Stop passed; retained original PDF bytes/hashes/highlights and fresh child Read were checked, not inferred from mocked HTTP success. Complete check commands, interrupted/initial attempts and subsequent focused scope are recorded in the [execution tracker](../execution-tracker.md); these are not full R1–R7 or real-model/corpus acceptance.
