# Prototype 01：聊天 → 原文 → 选区追问

> 2026-09-08 · D0 第一轮可交互原型，不是正式 Pi 产品。
> [ADR-022](../adr/022-prototype-first-delivery.md) 将原型评审放在后端迁移之前。
> 用户已确认现版原型，后端按 [详细设计](../architecture/backend-delivery.md) 开始推进；这里仍是可单独运行的 Demo 说明。

## 设计目标

先验证一条真正顺手的使用链：从一个居中聊天框开始，得到带引用的回答，点击后展开原始 PDF，定位具体区域，
选中一段继续问。用户不需要理解 Source Scope、Agent presets、轨迹事件或后端配置。

视觉：暖白纸面、深墨色正文、单一低饱和蓝色操作色、柔和黄色证据高亮；本地打包 Noto Sans SC 可变字体，不请求外部字体服务。
不使用装饰插画、渐变卡片墙或默认多栏 dashboard。
桌面阅读状态为原文主区 + 同一 chat，可拖动分隔线；手机在原文/对话间切换，共用草稿和选区状态。

## 视觉收尾与交互优化（2026-09-08）

用户已明确认可首轮功能，反馈集中于美观；本轮不重做功能布局，不增加首页面板，也不提前接入后端。

- 统一颜色 token、边框、圆角和阴影，移除遍布界面的浅绿配色；首屏标题、输入框、正文和辅助信息形成清楚层级。
- 答案正文 15px、分屏 14px，主要辅助文字 11–12px；手机输入 16px，保留留白与阅读宽度。
- 引用支持鼠标悬停/键盘聚焦预览：原句、来源文件、页码；Esc/失焦/滚动可关闭，鼠标可移入预览。
  预览不是第二个阅读器；点击引用仍直接跳原始 PDF，没有 Markdown 中转。
- 默认原文 58% / 对话 42%；分隔线可拖动、左右键微调，双击/Enter 恢复默认，Home/End 到边界。
  窄桌面保留原文至少 320px、对话至少 340px；手机不显示分隔线。比例仅为当次页面布局，不写画像。
- 选区卡片明确“仅本次提问”，可展开完整摘录、查看文件名、定位原文或移除；展开不触发发送/保存笔记。
  “问这段”后原文保留定位，键盘焦点留在输入框；缩放/调整分屏不抢焦点。
- 重复点击同一引用也会重新定位，避免用户手动翻阅后点击无反应；短屏首页可滚动，小屏仍能打开资料与设置。

这些优化不改变答案事实/引用集合，不引入自动学习、持久化或新的业务 wire 类型。用户随后确认沿用现版，首轮视觉评审通过。

## 首版实际可体验

| 交互 | 当前实现 | 验收重点 |
|---|---|---|
| 居中聊天 / 建议问题 | 三个明确的样例入口、文本输入、Enter/Shift+Enter、停止/新对话 | 空态干净；中文输入法不误发送 |
| 回答与逐处引用 | 预设摘要、营收、风险；每处引用绑定示例 document/page/quote | 不假装模型已运行；引用只针对样例 |
| 引用预览 / 阅读比例 | hover/focus 原句预览、拖动/键盘调整分屏 | 预览不展开 PDF；点击才导航；不丢草稿/高亮/键盘焦点 |
| 原始 PDF | PDF.js 真正渲染原始字节、翻页、缩放、选择文字 | 不是 Markdown 页面或重画的 HTML PDF |
| 引用高亮 | PDF 字节 hash 验证，原文字层唯一 quote 匹配，实际 DOM range geometry | 无 match/重复 match 不画框；只在原始页高亮 |
| 选区追问 | 实际选择→操作条→context chip→一次提问→回原文 | 来源/页/片段不丢；Ask 不自动存笔记 |
| 临时研究笔记 | 显式摘录、查看、返回原文、删除 | 仅页面内存，不冒充长期研究 memory |
| 资料面板 | 示例资料、浏览器本地 PDF、切换/移除 | 本地文件不上传；不套用示例答案 |
| 阅读偏好 | 简洁/分点两种排版，why-used 提示 | 事实/引用不变；显式选择，不自动学习 |
| 失败/控制 | 错误文件、未知问题、local-only 提示、取消和迟到结果屏蔽 | 不以伪造结果填补未实现能力 |
| 窄屏/可访问性 | 单面切换、语义标签、dialog focus/esc、reduced motion、axe | 主链能用，不能只有桌面截图 |

本轮没有 Claim/Review/Publish、真正跨会话研究、个性化自动校准、Compare、Pi tools 或真实模型调用。入口里的
“关于这个原型”列出真实/模拟/下一轮设计，避免将尚未实现的按钮摆成已完成产品。

## 推荐体验顺序

1. 点「总结这份报告」：回答明确标为示例脚本。
2. 悬停或 Tab 聚焦收入句旁的引用 1，看原句预览；点击后第 2 页 Q4 原文高亮，chat 草稿不丢。
3. 点区域/风险引用：第 3/6 页同样定位；关闭原文仍回到同一对话。
4. 拖动中间分隔线调整阅读比例；在 PDF 上拖选一段，点「问这段」，展开原文卡片检查片段后发送。
5. 选区→保存笔记→右上「笔记」→回到原文。
6. 选择「营收变化」：查看原表与明确标注的演示计算；Growth 口径未定义会被指出，而不是擅自称同比/环比。
7. 在阅读偏好切换简洁/分点：同一组事实和引用保持不变。
8. 打开自己的 PDF：文件留在浏览器，可读可选；全文问答明确未接入。

## 运行

~~~bash
bash scripts/pnpmw run demo
~~~

这会生成静态 build 并在 127.0.0.1:4175 启动带访问令牌的预览。打开终端输出的完整链接。
远程服务器使用端口转发，例如：

~~~bash
ssh -L 4175:127.0.0.1:4175 <你的服务器>
~~~

然后在本机使用同一 http://127.0.0.1:4175/?token=... 链接。不要把 Vite 或整个工作区文件目录公开到网络。

已有 build 可以只运行：

~~~bash
bash scripts/pnpmw run demo:preview
~~~

本地开发：先运行 build:demo 准备静态资源，再使用 pnpm wrapper 的 --filter @docatlas/web-demo dev。
该 dev server 仅供 loopback 开发；支持的对外转发预览始终使用有认证的 demo:preview。

## 验证与局限

- 当前验证：15 个原型 unit tests、14 个 Demo browser tests 通过；全工作区 401 JS / 76 Python、旧 DSH 6 个 browser tests 通过。用户已确认沿用现版原型。
- 原型纯状态/quote/geometry 单元测试位于 apps/web/test。
- 浏览器验收位于 e2e/demo/prototype.pw.ts，通过 `bash scripts/pnpmw run test:demo` 运行。
- 截图生成在 .cache/prototype-screenshots，仅为评审产物，不提交，也不自动代表用户认可视觉设计。
- 脚本回答对应当前固定 fixture，不处理任意问题；所有 unknown/local-only 路径有明确提示。
- quote selector 只有空白规范化，不模糊猜测；跨页/重复 quote/OCR/旋转的完整产品能力不由此保证。
- 自选 PDF 限 25 MB，最多四份；当前只同时渲染一个 source/page，不提供多文档 Compare。
- 单次选区最多 2,000 字符；暂不实现跨页选区、长期 pin 或生产级 Locator 重锚。
- 渲染像素和文字项有上限；大型/复杂 PDF 的完整资源隔离仍是生产 provider gate。
- 页面刷新会清空草稿、文件、笔记和偏好。预览认证不是正式多用户授权系统。
