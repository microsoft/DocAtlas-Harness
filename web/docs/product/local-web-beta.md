# 使用真实 DocAtlas Pi Web

> 本机/SSH 转发测试版。真实模型、真实 PDF 与持久会话；不是公开生产服务，也不是模拟原型。

在本项目目录运行：

```bash
az login
bash scripts/run-docatlas-web.sh
```

已有 Azure 登录时不必重复 `az login`。这是服务器调用模型的凭据，与网页登录无关。启动脚本先构建，再输出网址。
浏览器打开 **http://127.0.0.1:4177/** 即可使用，没有登录、配对码或登录有效期。默认是居中聊天；「历史」和原始 PDF 按需展开。

在远程服务器运行时，先在自己的电脑建立 SSH 转发（使用现有可登录的服务器名称）：

```bash
ssh -N -L 4177:127.0.0.1:4177 azureuser@t2vg-a100-G4-49
```

然后仍在自己的电脑打开 http://127.0.0.1:4177/。浏览器和服务器端口需保持一致，使用 `127.0.0.1` 而非
另一个 Host 别名，以符合现有 Origin/Host 校验。需要其他端口时两端一起调整，服务用 `--port 4178`。
能访问本机端口的人即可使用这个工作区，不要向公网或共享代理转发。Host/Origin/CSRF等跨站保护仍保留；这是单用户本机方案，见[ADR-055](../adr/055-login-free-local-web.md)。

## 文档使用

1. 在聊天框旁点击「上传 PDF」，或直接拖入页面，一次一份、最大25 MB。首次上传会自动建立会话，不需要先打开历史。上传即表示用于本次提问，只有完成索引并核对同版原件后才显示为已添加。
2. 文件名出现在输入框旁后直接提问，可继续添加多份文件。点击文件标签打开原文，×只移除本次提问关联；已有文档在「资料」中选择。Agent 使用渐进 Read，最终保存的回答才可能提供已核验原文引用。
3. 点击引用，原始 PDF 在旁边打开。只有同页唯一原文匹配才高亮；无法精确定位会明确显示整页/歧义状态，不跳 Markdown。
4. 可以主动打开原件、选中文字，再明确选择「加入问题」或「保存到研究」。前者核验后加入下一次问题，后者进入独立研究草稿；两者不互相代替，也不自动写入个人画像。
5. 以下能力均为可选，不是日常阅读门槛。Flash 增强在「资料」的文件卡片「更多」中显式启动，提供摘要/展开/完整增强与预算；其结果只辅助导航，不作为事实证据。
6. 文件卡片「更多」可将两份文档放入 A/B 对照；两侧的版本、页码、缩放/滚动和选区独立。引用跳转后可返回上一阅读位置，窄屏切换保留同一状态。
7. 顶部「Research notes / 研究笔记」可直接创建自由笔记、待研究问题、研究决策和研究规则，不需要先上传PDF或发送问题。手机在「Research / 研究工具」中打开。
   也可以从原PDF「保存到研究」创建带原文位置的笔记/问题，查看完整版本、编辑、归档/软删除，再回到原件。操作说明见下节。
8. 可以让Agent用`docatlas_record`记录研究checkpoint/问题、用`docatlas_recall`查找旧研究；无文档研究同样支持。
   召回是线索，旧文档仍须明确纳入和重新读取，不能用Note直接替代原文。研究的召回/贡献开关只控制Agent，和个人偏好分开。
9. 右上角「更多操作」→「偏好」支持手动枚举设置、两个独立开关、修改/暂停/忘记/导出。保存后开启「使用已有偏好」，下一次提问会按有效设置
   临时加入表达指导；「生成时采用」只在实际观察到模型正文后记录，不保证模型完全遵从，也不代表事实正确或最终发布。
   用户主动单变量呈现比较与跨研究学习见下节；没有被动习惯推断或强制弹窗，Reader不会自行重排。修改/暂停/忘记或关闭使用可能停止正在用旧偏好生成的回答；需要继续时明确重发新问题。
   未确认研究/偏好操作保留原 body/key/version，刷新不自动重发。贡献开关独立，不影响已许可的现有偏好使用。
   若另一标签页已清除画像，旧偏好请求会停止重试，不能恢复已清除设置；清除此本地草稿后，可重新明确选择。

引用的「支持/反驳/限定」是 Agent 对关系的判断；位置核验不等于语义审阅。没有映射、未知 Locator、截断回答
不会被伪装成可靠引用。目前原生通用工具可在独立工作目录中使用；新增本地人类Claim/Review流程如下。
显式版本、有界Continuity、主动比较与同意后的低频邀请/跨研究明确选择积累已接，使用方式见下；被动习惯推断、漂移重学、完整研究恢复与更多原生管理 UI 仍未完成。

## 发送与断线反馈

发送消息时，回车和发送按钮使用同一路径：先显示本地“发送中”气泡，收到确认后再交接到真实记录。原请求/附件/选区并未被视觉清空删除。若显示“尚未确认”，使用原键重试或明确清除本地待办；不要把这个状态当成已保存。Shift+Enter换行，组合输入期间不提交；刷新不自动重发。新建会话仍须先完成真实会话建立。

## 独立记录研究，而不必先提问

1. 打开「研究笔记」新建记录，选择笔记、待研究问题、研究决策或研究规则。默认不关联资料；需要时在「明确关联资料」自行勾选，既不改变下一问来源，也不授予Pi新的访问范围。
2. 在A/B任一原PDF选中文字后点「保存到研究」，填写自己的理解或问题，再确认保存。服务器独立核对整组原文；不要求加入问题托盘、不消耗票据、不发送模型请求。一条记录最多8段、共8000个原文字符。
3. 列表可切「当前研究 / 工作区历史」，按类型、状态筛选。点击「查看研究全文与版本」后才编辑，不能拿列表摘要覆盖全文。笔记/问题初建最多4000字符；笔记编辑最多8000，问题编辑仍为4000；决策/规则正文最多8000字符。修改保留旧版本；问题可标记解决，记录可归档或软删除。
4. 原件的研究标记入口按精确版本和页面查看已保存锚点，可回到原始PDF定位。原文位置只是位置核验；笔记解释、研究决策和规则都不是新的事实证据，不能直接用于支持回答。规则的声明范围不会自动让Agent继承或执行它。
5. 网络结果不明时，保留原操作并使用原键查询/明确重试；刷新不自动重发。只查到原回执不恢复已经软删除的正文。「仅清除本地待办」不撤销服务端可能已保存的内容。未提交编辑草稿不保证跨会话或分支切换保留。

「Agent 研究设置与托盘笔记」保留此前的研究许可和已核验托盘笔记入口。人类手动保存、Agent研究贡献/召回和个人偏好是三个独立选择。
软删除仍保留历史，并非隐私擦除或完整备份恢复。[ADR-052](../adr/052-human-research-authoring.md)说明数据和授权边界；实际验收见[任务板](../execution-tracker.md)。

## 文档地图、摘要与研究更新

- 原PDF工具栏点「Map / 地图」查看章节。选择节点查看已有摘要，尚无摘要时可明确确认生成；普通打开地图不会调用模型。
- 「Original / 原始结构」只看原目录；「Research / 研究视图」叠加带来源锚点的笔记、问题和关联结论/审阅。青绿表示新增研究，琥珀表示记录已修订，另有类型和版本文字，不表示“事实已通过”。
- 点击研究节点可回到原PDF位置，也可打开完整笔记或审阅记录进行编辑。地图根据记录更新；软删除撤下标记，不改写原目录。
- 同页多个章节不能证明笔记属于某一小节，因此关联到共同祖先/文档。没有原文锚点的自由笔记仍在笔记工作区，不编造地图位置。研究记录、关系图和章节有显示数量上限，截断时有提示。
- 选区提问提交后，问题保留原始摘录，回答有可展开的选区上下文；刷新后仍可据原提交回到同一原件位置。

## 让 DocAtlas 学习你的呈现偏好

### 跨研究积累与可选提示

打开「偏好」→「管理偏好学习与可选比较提示」。独立的回答下方单次比较入口已移除；已有选择与此处受控学习不被改写。

1. 可选开启「允许偶尔建议阅读比较」。默认关闭；它不会替你开启当前会话的“积累信号”或“使用已有偏好”。新完成且有原文证据的回答，在当前会话至少完成3次提问后才可能出现一行邀请；每项研究最多一次自动邀请，整个工作区画像还有10分钟冷却。不会弹出遮挡阅读的窗口，也不会为比较再问模型。
2. 不想等提示时，可在学习面板主动选择一份已保存回答。准备比较后，两边使用完全相同的回答、证据和不确定性，只交换回答/证据的先后顺序；引用仍打开原始PDF。
3. 默认仅记录本次选择。只有明确选择「用于未来工作区偏好学习」的具体顺序才参与积累；浏览、关闭、忽略、两者都可/都不合适均不推断长期倾向。
4. 在同一任务模式中，至少3个独立研究选择同一顺序，且没有相反选择，才出现待确认候选。重复点击、同一研究的多次比较和会话分支不增加独立研究数量；不能访问某个原来源时，整组暂停展示计数和确认，而不是忽略它。
5. 单独确认后才采用为工作区默认；后续应用仍需“使用已有偏好”许可。已有偏好、已处理或已忘记的候选不会被旧投票重新创建。跨模式适用性与长期效果尚非已证明，仍可在偏好中心修改、暂停和忘记。

断线保留原请求，通过「只读核对」查询或显式原键重试；第一、二次选择当时没有候选的回执，之后也不会被改成“当时已生成候选”。邀请记录仅表示系统分配过一次邀请，不表示用户已经看过。[ADR-054](../adr/054-consented-preference-learning.md)与[任务板](../execution-tracker.md)记录准确验收范围。

### 已移除的回答面板

按用户要求，回答下方的「About these sources」「Answer options」及独立的单次样式比较面板已移除。正文引用按钮仍直接回原PDF，来源不足不会因此变成有效引用。旧比较记录、原请求和后端恢复规则保留，不自动重发、不清除数据；新的自然交互入口留待后续设计（ADR-062）。

## 文档版本与继续旧研究

1. 在「资料」的对应文档点击「版本与更新」，选择 PDF 作为此文档新版本。系统核对原当前版本再保存；不会根据文件名猜关联，也不会覆盖旧 PDF。普通上传仍是独立资料导入。
2. 历史中可打开旧原件、放入 A/B、分别勾选新旧版。上传成功不会自动升级提问来源；需要比较时明确选择两版，并让 Pi 读取原文、完成带引用的回答。
3. 对已保存的笔记、结论版本或成果点击「继续核验」。选择「连续研究阅读范围」，勾选本次来源，以及旧侧/本次侧的新读取证据；可逐项点击「核对原始 PDF」。未保存的编辑草稿不被提交或覆盖。
4. 可展开「版本依赖检查（只读）」：它只提示旧记录是否引用了该版本，不判断内容是否相同。选择「仍然适用 / 已有变化 / 存在冲突 / 尚不能判断」，填写依据，再「保存这次人工判断」。材料不完整时不能选比较性结论。
5. 这是独立的 ContinuityLink，固定原记录版本、两侧来源和证据，不修改旧笔记/结论/已发布成果，也不写入个人偏好。笔记正文仅作旧研究线索，不能替代这次原文核验。

版本导入和人工判断都保留未知结果的原请求。刷新只查询，不重发；需要继续时使用面板上的原键操作，不能换目标或重新生成请求。
「仅清除/弃用本地待办」不撤销服务器可能已提交的结果。历史版本相同bytes重导入不执行回滚；直接打开原历史版本即可。
新导入已将文档和成功回执同事务保存。旧孤立回执仅可由原键显式修复，系统必须核对完整原始记录，不能按最新版本猜成功，也不重新解析PDF；普通刷新不执行修复。仍不承诺完整host异常接管或自动续传。完整验收见
[ADR-046](../adr/046-explicit-revisions-and-continuity.md)和[任务板](../execution-tracker.md)。

## 结论、审阅与本地成果

打开顶部「Findings and review / 结论与审阅」（手机在Research菜单）。这是按需展开的人类工作面，不要求每次聊天都创建结论。

1. 选择「审阅资料范围」，核对证据预览并点击「核对原始 PDF」。可以选择仍获授权的历史范围；这不会改变下一次问题的资料选择或Pi原生范围，也不会自动把旧证据借给新范围。
2. 写下结论，明确支持/反向/限定等关系、证据判断与人工审阅状态，再保存。修订按原ClaimVersion条件产生新版本；历史不原地覆盖。由已有结论推导时列出输入，计算还需表达式/舍入说明，系统不保证已验证算术。
3. 在「成果与审阅」选择已保存的结论与用途，创建Brief或Matrix草稿。成果引用仍回同版原始PDF；没有可核验证据时不出现示例结论填充。
4. 人工核对列出的材料并保存声明，再「运行 G0–G4 审阅」。该声明不是“已穷尽所有外部反证”；列表截断时不能作完整材料声明，规则失败也不能用人工批准跳过。
5. 对固定审阅结果单独批准或拒绝。发布需要该Review最新的有效人类批准；后续拒绝会阻止用旧批准发布。确认后「发布本地成果」只保存本地不可变记录，不发送到外网/他人。
6. 「Relationships / 关系图」显示已存Evidence→Claim→Artifact→Review关联。支持、反驳、限定有不同线型，点击卡片查看直接关联并回原文。G0–G4与人工批准仍是独立步骤，关系图不产生新的事实判断或通过分数。

已发布成果不能原地撤回或覆盖；「复制为修订草稿」当前创建新成果链，需要重新审阅。后续拒绝不抹掉已发布历史。
网络中断或回执不确定时，用「使用原键核对操作」显式对账；刷新不会自动重发，切换范围不会替换旧body/key。
「仅清除本地待办」不撤销服务器上可能已经提交的操作。

该流程复用原Answer/selection证据及M4 journal；Note正文、Recall线索和个性化不能成为事实支持。
当前定向真实HTTP/Pi与browser旅程已通过，供应端是明确faux测试；整套验证、真实业务/语义质量与恢复边界见
[ADR-045](../adr/045-local-human-review-workbench.md)及[任务板](../execution-tracker.md)，不据此宣称正式发布完成。

## 原生运行设置与更早的消息

顶部「运行设置」按需展开。可以在第一个问题之前分别保存模型、思考档位、插入队列或跟进队列模式；不会生成聊天回答，也不修改提问草稿和选中文档。目录来自服务批准的模型与Pi实际能力；只批准Luna时不会显示虚构的其他模型。

这些是当前原生会话配置，不会自动成为你的长期个性化偏好，也不是研究记忆或事实证据。

「已接受/正在应用」不是成功，核验原生持久回执后才确认。网络断开会保留本标签页原键、完整操作、批准版本和原生前缀。「刷新」只读；「使用原键核对」可找回已提交证明，不重复执行结果未知的设置。未决操作会阻止继续执行，包括冷启动扩展；清除本地待办不绕过服务端屏障。面板有原生任务停止入口，仍需等待实际执行结束。

消息上方「加载更早消息」读取原生记录，不重发旧问题。完整旧回答仍可点击引用回同版原始PDF。原始用户问题已清除或不能精确对应时明确显示不可用，不把模型收到的附加上下文冒充原话。游标过期或新checkpoint出现后需重新加载；单页和同时显示的历史有容量限制，原始会话文件未删除。

在同一面板的「上下文管理」中，可以使用「压缩当前上下文」，并填写可选的「压缩时特别保留」。只有Pi当前有可压缩内容、执行与队列空闲、没有未决操作时才开放。它调用当前模型，可能产生费用；缩短的是后续提问的模型上下文，不删除完整聊天、研究笔记、个人偏好或原PDF引用。摘要可能省略细节，也不能当作新一轮事实证据。

成功回执显示真实Pi压缩记录，不伪造一条助手回答。正常取消/SDK拒绝若被独立核验为没有写入压缩记录，会显示「已核验未应用压缩」，等待停止确认后可继续提问；它不表示撤销模型费用或扩展的外部效果。无法证明的情况仍保留原键等待核对。压缩后旧引用继续打开原版PDF，新问题需要重新读取原文才能获得新核验引用。

### 分支与子会话

入口为「运行设置」→「分支／会话树」，已通过真实本机Pi/PDF浏览器旅程，准确范围见任务板第二十四批。页面仍默认只显示聊天，不常驻复杂树形布局。

1. 「刷新分支树（只读）」查看真实Pi节点，可切换消息/全部公开条目。工具、thinking和内部元数据不会以原始正文显示；原始用户输入无法对应时没有预览，不用模型收到的附加上下文代替。
2. 选择节点后「切换到这个原生位置」，可显式要求Pi生成分支摘要。选择用户消息时，原生语义是返回其父位置；不会自动将预览或SDK editorText写入你的提问草稿。摘要可能调用模型并产生费用，不是新Evidence。
3. 「从此节点创建子会话」保留父会话，创建独立的原生子会话；用户节点还支持在其之前创建。等待「已核验完整交接回执」后，明确刷新当前分支或打开子会话；接受/交接中/结果未知均不算完成。
4. 断线不自动重跑。保留完整原键、原节点和批准信息，用「仅查询原分支操作」检查，或明确「核对／继续完成原操作」。即使当前会话代际已经改变，也只核对原操作，不能按新树重新拼命令。
5. 继承或旧分支回答明确标出历史归属，引用仍打开当时同版原PDF。新问题要明确选择资料并重新Read；旧选区票据不自动转移。分支切换不会撤销Note/Claim/Review/个人偏好。

新网页的「停止」固定发送时的会话绑定；若期间已经切换分支，旧请求会得到冲突提示，不会转而停止新代际任务。停止响应仍要等真实执行结束，不把点击按钮等同立即完成。

同会话的旧Answer仍可用于原有研究/呈现比较。跨会话继承的Answer保留原归属，呈现偏好比较须回原会话，不能把同一份回答重标后重复投票。
撤销文档访问并不擦除已经归你所有的Pi聊天记录；重新打开结构化Answer/证据/PDF仍会检查原会话及来源权限，失败时不把聊天文字当获授权的原文。

完整扩展Web对话框、自动in-turn compaction/steer等复杂出处边界仍另行验收。参见[ADR-048](../adr/048-native-operations-and-history-pages.md)、[ADR-049](../adr/049-manual-native-compaction.md)、[ADR-050](../adr/050-native-lineage-handoffs.md)与[任务板](../execution-tracker.md)。

## 状态、模型与关闭

默认状态目录为 `.cache/product/`，和既有 DSH、原型数据分开。里面区分原生工具工作区、Pi 会话、文档缓存、上传与私有
产品数据。可用 `--state-root /独立目录` 选择另一套状态，不要直接指向原项目或旧数据库目录。
Ctrl+C 正常关闭并封存会话；重开同目录保留历史。未核验的异常退出不会被自动当作安全恢复，不要删除锁或 claim 来强行启动。
完整状态还包括研究capture/provenance、独立profile、文档原件/缓存与运行记录；只复制某一个SQLite文件不是完整备份。
正式一致性备份/异常恢复的操作流程仍在发布计划中，本版不提供自动接管或一键恢复承诺。
此前profile元数据v1→v2升级引入非内容擦除代际，用于阻止旧请求复活；升级产生的受管备份仍纳入完整画像擦除。
独立人类研究使用同一个领域数据库的v5→v6升级，首次打开旧库时先生成受管v5备份，再以事务增加投影表；不能把v6库交给只支持v5的旧程序，或修改版本号强行降级。此次开发只验证临时库，未操作用户现有数据库。升级备份不包含整套PDF/native/profile状态，不能当完整产品备份。
跨研究偏好学习的profile元数据升级为v3，v2→v3先备份，保留原擦除代际与旧偏好/回执；v2或更新库丢失擦除代际会拒绝打开，不按0重新初始化。产品已有偏好HTTP仍保留v1/v2原语义，新学习使用独立接口。不要让只支持旧profile schema的程序打开新库。

Flash新增强作业显式使用`docatlas-flash-enrichment.v2`，最多同时处理两个独立节点，并共享整项预算；失败/取消仍等待所有实际调用结束。旧待办缺省继续v1，不会因刷新被升级或重新生成已保存结果。并行不代表所有文档都有两倍速度，也不是OCR/真实语料质量保证。

## 文档结合代码和本地成果

DocAtlas保留Pi原生文件和Bash工具。选择PDF后，可以要求先读取原文，再编写可复跑脚本、保存输入并执行计算，输出CSV、SVG或Markdown。成果保存在启动终端显示的原生工作目录（默认`.cache/product/workspace`），不是自动发布到研究成果区，也不是新Evidence。

例如：“读取第二页的Q4数据，把原始输入和引用ID保存下来，编写Node脚本计算Q4乘四的示例值，输出CSV、SVG及说明报告；明确标注这只是示例年化，不是原文全年收入。”本机补验已核对实际文件、脚本执行、输入哈希与原PDF引用。模型决策在这条自动化测试中是脚本控制，不能据此保证任意真实模型都正确选择工具或处理任意业务公式。

取消提问资料选择后仍可继续普通代码任务；这会取消新问题的文档工具准入，不会抹掉原生历史、已保存文件或历史研究scope。旧引用在权限仍允许时保持原出处。需要正式派生Evidence/审阅/发布时，请使用相应独立流程，不能把可打开的成果文件当作已经核验。

默认launcher只批准用户指定 Azure 资源上的 **GPT-5.6 Luna**，由 Pi ModelRuntime 走 Responses；运行设置不允许浏览器注册任意provider。DocAtlas 不将模型令牌写入
自己的文件、浏览器或 Pi 记录；Azure CLI 仍使用用户原有的登录缓存。费用元数据来自 OpenAI 参考价，不代表 Azure 合同账单。

`trusted-resources/` 默认空。添加 Skills/extensions 等资源后，服务会要求核对精确 snapshot hash，再以
`--resource-hash <已审阅的SHA256>` 启动；来源内容改变需要重新审阅，不自动执行上传文档中的代码。

bash scripts/pnpmw exec node scripts/test-pi-pdf-live.mjs --live
